# 并行开机初始化与验证记录

实现日期：2026-09-17。基于仓库《开机初始化初步优化方案.docx》及实际代码；本文件描述已实现行为。未刷写设备。

## 启动链路

电源保持 → 电源管理 → 一次必要电池 ADC 诊断
↓
基础初始化：OTA 镜像识别／PENDING_VERIFY 下 NVS 保护 → NVS、netif、默认事件循环 → 共享 I²C
↓
语音服务装配（观察者、主题）→ 注册 MQTT／WSS／SNTP 联网回调
↓
并行执行，各分支内部保持顺序：

① 背光初始化 → LCD／LVGL → Avatar → 开机动画

② 板级音频 → 语音缓冲／播放任务／音频回调接线 → 音频服务 → 按配置准备本地 WakeNet

③ 时区与 RTC 恢复尝试 → Idle 资源 → FSM 资源 → IMU 硬件准备（采样关闭）

④ 启动已有 Wi-Fi 生命周期 → 后台扫描／关联／获取 IP／失败重试

显示资源（背光/LCD/Avatar）成功 ＋ ②音频成功 ＋ ③本地资源成功
↓（不等待动画结束）
协调者激活 FSM 的 S0 握手处理 → 提交运行期电源配置 → 建立首次云连接期限
→ 开放 MQTT/WSS 门控 → 主动重试；已有 IP 即握手
↓
MQTT/WSS 握手和语音会话同步，与剩余开机动画并行
（此时动画独占画面；云端先就绪也不进入 S3，不开放业务交互）
↓
全部本地分支和动画完成
→ 在 S0 初始化夜间/运动/静默管理
→ 通知 FSM 交出画面；异步电池监测和待验证镜像验收继续推进
↓
动画已结束 ＋ 已得出联网判决：
业务 ONLINE → 进入 S3 STANDBY，不显示 offline
首次连接超时 → 进入 S3 STANDBY，显示 offline，继续后台重连

如果动画结束时连接仍未判决，则固定开机亮度（当前 50%），显示 S0 CONNECTING；成功或原有 30 秒期限到达后才进入 S3。期限从提前开放门控前建立，不在动画结束时重置。

SNTP 是独立依赖：时区设置与 RTC 恢复尝试结束后即可启动，无需等待动画或 RTC 恢复成功。恢复尝试结束会主动通知服务重试。SNTP 校时与启动 RTC 恢复不再竞争写系统时间。

例外：显式启用的 pending 镜像 GPIO 诊断仍在基础初始化期间、外设启用前执行。当前诊断 GPIO4 与 `JULIA_LED_GPIO` 重合，不能把会重配/复位该 GPIO 的操作搬到运行期。其 5 秒等待不属于普通启动，也没有计入提速收益。

## 协调、依赖与生命周期

- `app/boot_coordinator.c` 只协调三个本地分支，不另包一层 Wi-Fi 任务，也不是通用调度框架。
- 每个结果分别表达 `completed` 和 `error`。分支是对应模块结果的唯一写入者；队列复制结果（显示分支另有资源成功里程碑），并建立分支局部结果向汇合方的发布关系。任务创建失败立即产生 `ESP_ERR_NO_MEM` 完成结果。
- coordinator 和成功创建的每个 worker 各持一个上下文引用；正常汇合后最后一方释放队列与上下文，worker 自删。超时后 coordinator 释放自身引用；晚到 worker 仍可安全发布和释放。不会强删持有驱动锁的任务。若驱动永不返回，该 worker 的引用随设备故障停留/复位保留，不能冒险回收。
- 共享 I²C 第一次创建必须在分支前成功。失败时直接故障处理，不启动任何消费者，不让 RTC、IMU、LCD 并发重试创建同一总线。
- FSM `prepare()` 创建队列、未武装计时器和等待控制命令的 owner，不操作画面、不启用业务定时、不发布可运行状态。普通异步/同步事件在激活前被拒绝；激活后的 S0 仅允许连接事件及无行为副作用的会话重置，不积压唤醒、OTA 或运动。
- FSM `start()` 由 owner 激活 S0 握手、发布 S0 快照，不改画面和背光，也不迁移 S3。`finish_boot_animation()` 在本地汇合后才发布首次观察者通知、设置等待亮度并尝试 S3 交接；云判决先到时锁存在服务状态中。观察者在语音装配阶段注册；夜间、运动、静默任务在 S0 启动时主动读取当前快照，避免依赖一次可能已错过的通知。
- `start_cloud_window()` 在 owner 上更新期限/计时器，并同步确认。门控开放顺序严格晚于确认；重复调用不重置初始期限。计时器不可用时仍由 owner 的截止时间巡检兜底。
- Idle 准备态为 STANDBY，其任务阻塞等待通知，不投递超时行为；播放 worker 可提前阻塞待数据。WSS 回调发布前上行缓冲、采音上下文和播放 worker 已准备好。
- 本地 WakeNet 在音频分支完成，纳入本地期限。未 ONLINE 时不接受唤醒、不喂入可重放的离线音频；恢复时换代并清空旧 AFE 数据。
- IMU 硬件配置完成时保持采样关闭。部分配置失败回收设备句柄；只有硬件准备成功且本地资源汇合完成才在 S0 创建运动任务；采样仍等 S3 等适用状态。
- 夜间、运动和静默管理在 S0 由独立临时任务初始化。夜间仅在 S1/S3/S5 计宽限，IMU 在 S0 不采样，静默管理在 S0 不暂停网络；S3 状态通知自动推进其运行行为。电源配置提前到握手依赖满足时提交，随后直接推进云分支；电池监测在本地汇合后异步启动，不阻塞云握手。电池 worker 只创建常驻监测任务后退出，启动 ADC 采样早已结束；不会同时调用阶段电压采样。

## 超时、资源与故障

`CONFIG_JULIA_LOCAL_INIT_TIMEOUT_MS` 默认 **20000ms**，与云端 **30 秒** 独立。计时从启动本地分支之前开始，覆盖提前云门控回调的执行，采用单调时钟绝对期限，队列按剩余时间阻塞等待，不忙轮询。

本地期限的工程预算来自当前路径：动画固定保持时间 300 + 8×(255+120) = 3300ms，LCD 有 20ms/120ms 复位和命令等待；I²C 单次事务有 100ms 超时；音频包含内存、I²S、任务创建，可选 AFE/模型加载。20 秒是允许最坏耗时的截止策略：为显示链分配约 5 秒、可选模型链约 12 秒、资源链约 3 秒的预算，以最长分支加约 8 秒调度裕量设置，**不是实测最坏执行时间保证**。新增模块或模型后应根据分支日志重审，不能拿云端 30 秒代替本地期限。

本地临时任务优先级为 3：显示栈 6144B、音频 8192B、资源 4096B；FSM/Wi-Fi 保持各自现有优先级 4，音频实时任务保持既有配置。worker 退出前记录栈高水位。三条临时分支约增加 18KiB 活跃栈需求，汇合后释放；需用实机日志确认最小堆和栈余量。

| 情况 | 处理 |
| --- | --- |
| 背光、LCD、Avatar、板级音频、语音接线、音频服务、Idle、FSM、所选本地唤醒失败 | 关闭云门控；保留对应显示/音频/语音/FSM 故障分类，走 S7.2 故障恢复；pending 镜像先拒绝/回滚 |
| 动画失败但显示仍可用 | 恢复受限背光，允许静态画面交接；动画错误单独记录 |
| RTC 不存在、无效、读取失败 | 完成恢复尝试并放行 SNTP；无有效时间时夜间策略继续遵守原检查 |
| IMU 准备失败 | 不启用运动任务；现有静默管理继续按输入健康策略处理 |
| 夜间任务失败 | 记录降级，不伪装关键初始化失败 |
| 静默管理/运行行为任务创建失败 | 故障处理，门控失败锁存，避免随后云分支重新放行 |
| 电池监测不可用 | 记录错误，沿用监测不可用的降级 |
| 本地任务创建失败 | 对应结果立即完成且失败，无永久等待 |
| 本地超时或无 FSM owner | 不抢占仍运行的动画、不调用晚到驱动；记录 S0 来源故障并按原复位上限策略处理 |
| 网络生命周期创建失败 | 本地照常交接；app task 保留现有有界指数退避创建重试 |
| Wi-Fi/RTC/IMU/夜间功能编译关闭 | 不要求禁用模块成功；关闭 Wi-Fi 返回 NOT_SUPPORTED 后不继续创建重试 |
| IMU logger 模式 | 保留独占实验启动路径、基础准备及本地 OTA 验收，不运行产品启动分支 |

## 云状态与交互

连接判决已移入 S0。长期存活的 FSM 信号量负责通知 app，有限等待超时不会留下失效对象。网络生命周期创建失败时，app 等待该通知的同时按原退避期限重试创建；正常情况直接阻塞等判决。返回的是锁存的交接结果，不因 S3 后快速进入 S4 而误报启动失败。


| 服务状态 | 启动/待机呈现 | 准入 |
| --- | --- | --- |
| CONNECTING | `S0 CONNECTING`，固定开机亮度 | 本地资源已就绪，继续等首次判决，不接受业务交互 |
| ONLINE | `S3 STANDBY`；清除红色 offline | MQTT ready、WSS ready、语音会话同步 ready 同时满足才可交互 |
| OFFLINE | `S3 STANDBY` 和现有红色 `offline` | 保留本地行为和后台重连，丢弃不可用交互 |

首次 30 秒不是固定延时：可以提前上线，成功即取消计时。初次成功或超时才由 S0 迁移 S3；不把本地失败伪装为 OFFLINE。ONLINE 后旧超时因期限已清空而被拒绝。后续断线保留 S7.1、提示声音、会话清理与后台恢复策略。

在事件生产、FSM 消费及语音唤醒入口分别检查准入。未就绪的唤醒不会先修改 busy/round/播放状态再被拒绝；离线运动不排队等待联网。兼容的关闭本地采音配置中，“运动只恢复到 S3”的本地行为仍保留。

## OTA 与诊断

提前保留镜像状态识别、pending 下 NVS 不兼容不擦除保护、基础网络设施及回滚对账。普通启动不再执行额外健康测试。pending 镜像在本地资源就绪后的 S0 阶段异步检查本地分区/Flash/堆/队列、产品钩子并确认，失败仍拒绝镜像；无可回滚镜像时不会先标记唯一镜像无效。确认及状态对账完成前，OTA 引擎入口拒绝下一次升级。

原代码有五次阶段 250ms 等待和末段 1500ms 等待，合计移除 **2750ms 显式延时请求**。电压采样从 8 次合并为启动 1 次，当前每次 16 次采样、每次让出 1 tick，100Hz 下约 160ms 等待请求；额外 7 次约 1120ms 的采样等待不再串在启动路径。上述是相对原串行初始化的代码路径核算，**不是实机净提速数字**。当前方案把联网判决移回 S0，相比上一版“本地就绪即进 S3”，S3 可再延后 0～30 秒（另有任务调度延迟），取决于业务连接速度；并行初始化收益仍保留。LCD 复位、设备稳定、动画保持、故障复位和网络重试的必要等待保留。
