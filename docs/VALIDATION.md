# 验证与验收

文档版本：V1.0。本文给出执行方法与记录要求，不将未执行的硬件项目标为通过。返回 [项目入口](../README.md)。

## 1. 验证范围与状态

2026-08-30 的当前工作区已完成 ESP-IDF 5.5.4 完整构建，以及 `build-ota-name/julia_fused_base.bin` 的离线镜像检查：项目名 `julia_fused_base`、应用版本 `0.1.0`、文件大小 1940000 字节，镜像内部校验有效。该记录只对应当时的工作区和构建产物，不能替代任意 Git 提交的重建结果。

本版未包含完整上板、服务器联调或功耗测试的通过记录。以下表格是执行清单，不是已经通过的测试报告。仓库的 `check_lex_balance.py`、`verify_comments_only.py` 是辅助脚本，不构成端到端测试套件。

## 2. 测试记录

每次运行记录：源码提交号及未提交差异、SDK／工具链版本、配置文件摘要、镜像 SHA-256、板卡版本、device_id、供电、串口、服务器版本、网络条件和测试时间。

涉及语音时，记录音量、距离、背景噪声、音频样本编号和唤醒模式；涉及性能时，同时保留原始样本、样本量、失败数以及 P50／P95。凭据与用户原始语音不得直接写入公开记录。

结果使用“通过／失败／未执行／不适用”；已知缺陷不能通过修改预期值变为通过。文档中的数值默认是当前配置或格式推算，除非明确标为测量结果。

## 4. 启动与显示

| 编号 | 场景 | 核对内容 |
| --- | --- | --- |
| BOOT-01 | 正常冷启动 | 首屏、一次开机眨眼、本地初始化、网络启动分别有时间记录 |
| BOOT-02 | 无 Wi-Fi、错误密码或服务端不可达 | 本地显示可工作；记录各连接的重试行为，不将失败连接视为启动成功 |
| UI-01 | 正常 MIC_START → MIC_STOP → SPKS／PCM → SPKE | 听／想／说／待机相位、嘴型和忙碌标志一致 |
| UI-02 | 非 busy 待机超过 300 秒 | 远场待机、闭眼与背光呼吸；同时检查 MIC 仍按服务器模式上传 |
| UI-03 | 听音、思考或播放超过普通闲置阈值 | 不被普通闲置策略抢占；业务等待超时按已知限制记录 |
| UI-04 | 有效 RTC／SNTP，覆盖 22 点、23 点、07 点 | 睡前／夜间宽限和恢复符合状态条件；手动休眠不被晨间强制释放 |
| UI-05 | 无效 RTC／未同步时间 | 夜间调度不依赖无效墙钟误触发 |
| UI-06 | 允许的休眠／远场状态下移动设备 | 运动确认和冷却生效；播放中不触发 IMU 唤醒 |

## 5. 语音与协议

| 编号 | 场景 | 核对内容 |
| --- | --- | --- |
| VOICE-01 | 默认模式建立 WSS | 未发 MIC_START 前已有 PCM1，界面保持待机 |
| VOICE-02 | 接收一段 PCM1 | 魔数、载荷长度、序号、字节和正确；记录缺口，不假设跨会话清零 |
| VOICE-03 | MIC_STOP 后观察上行 | 仍有 PCM1，进入思考；不得按“麦克风静音”验收 |
| VOICE-04 | 16kHz／24kHz 播放 | 顺序为 SPKS → 偶数字节 PCM → SPKE；音量、声音和嘴型合理 |
| VOICE-05 | 未开播 PCM、奇数字节 PCM、超长消息 | 不把非法音频送入播放；连接关闭与忽略行为按协议记录 |
| VOICE-06 | SPKS 后延迟首包，或播放中暂停超过 750ms | 记录播放标志清除与后续丢弃，作为已知缺陷验证 |
| VOICE-07 | 播放时 MIC_START，并注入迟到 SPKE | 测量停播延迟及相位变化；记录缺少轮次关联的风险 |
| VOICE-08 | 服务器持续心跳但不返回回答 | 检查是否长期停在 THINK；当前没有业务超时兜底 |
| VOICE-09 | WSS 断开并恢复 | 上传／播放停止和重连正确；确认 UI、队列与首批新音频行为 |
| VOICE-10 | MQTT 单命令及不支持命令 | 只有三类作业可执行；不等待不存在的 vstatus 回执 |
| VOICE-11 | 本地唤醒配置单独构建／烧录 | 模型分区、识别与采音链路有效；不得仅凭服务器模式构建认定通过 |

## 6. 文件与 OTA

| 编号 | 场景 | 核对内容 |
| --- | --- | --- |
| FILE-01 | 外发存在的 WAV | BEGIN 大小、实际字节数和 END 一致；内容可独立校验 |
| FILE-02 | 无卡、文件不存在、错误扩展名、超限文件 | 正确拒绝；不格式化用户卡 |
| FILE-03 | 读取中断或连接中断 | 不接受截断文件；服务器接收超时和设备收尾有记录 |
| OTA-01 | MQTT 连接与 critical SUBACK | 发起 ota_check，身份及当前版本正确 |
| OTA-02 | 合法／缺少 schema_version 的 ota_notify | 合法通知触发检查；缺少 schema_version 的通知被拒绝 |
| OTA-03 | update=false 与合法升级清单 | 身份、request_id 和清单必填字段符合协议 |
| OTA-04 | 不匹配身份、过期时间、错误摘要或镜像名 | 拒绝安装；不能通过 force_update 绕过非版本校验 |
| OTA-05 | 完整 HTTP 200 下载 | 实际字节、镜像头、SHA-256、启动分区和状态正确 |
| OTA-06 | 下载中断后返回 206 | 当前预期暴露 RANGE_MISMATCH 限制，发布前需有明确处理结论 |
| OTA-07 | Range 请求返回 200／416 | 记录是否从零下载；不得算作 206 续传通过 |
| OTA-08 | 测试镜像启动失败、无网络、可回滚／不可回滚 | 本地验收、回滚／安全模式与报告关联正确 |
| OTA-09 | 报告期间断网、重复 PUBACK、队满 | event_id 幂等；容忍重复和中间状态缺失，不误判安装完成 |

故障注入使用专用测试设备和镜像，保留串口恢复方法；不能在用户设备上随意断电、损坏存储或烧写安全 eFuse。错误摘要与版本示例不发布给正常设备。

## 7. 性能与功耗指标

| 指标 | 测量定义 |
| --- | --- |
| 首屏时间 | 上电／复位到第一幅稳定可见画面 |
| 可对话时间 | 上电／复位到语音会话可接收有效用户话语 |
| 唤醒漏检率 | 已标注唤醒样本中未成功进入听音的比例，分距离与噪声统计 |
| 误唤醒率 | 无目标唤醒词音频中的误触发次数／小时 |
| 回答首音延迟 | 用户话语结束到扬声器首个可听回答；设备／服务端阶段分别打点 |
| 打断停播延迟 | 用户插话开始或服务器确认到实际声音停止，注明采用哪个起点 |
| 上行丢帧 | PCM1 seq 缺口、入队失败和连接切换分开统计 |
| 播放稳定性 | 首包延迟、断流次数、最长停顿、播放恢复方式 |
| 内存与调度 | 内部 RAM／PSRAM 余量、最大连续块、任务栈余量、队列高水位 |
| 显示性能 | 实际刷新时间／帧率、撕裂和嘴型偏移，不用任务周期代替 |
| 状态功耗 | 在固定电源、电压、亮度、网络与音量下测各状态平均及峰值功耗 |

产品目标需在规定测试条件下确定；本版不提供未经测量的性能达标值。平均功耗按各状态实际驻留比例加权，电池容量还需考虑转换损耗、可用容量和峰值电流，不能只按待机电流估算。

## 8. 发布门槛

- 构建、镜像属性和目标硬件匹配，配置与产物可追踪。
- 核心启动、正常对话、停止／打断、断网恢复和 OTA 完整安装有实际记录。
- 已知问题逐项标注影响、适用场景及是否阻止发布；不得隐藏 Range 恢复或业务超时限制。
- 生产认证、服务器身份、凭据、用户采音告知与数据保护有明确配置和验证。
- 不以“编译成功”“MQTT PUBACK”或“已写入 OTA 分区”替代整机运行与安装成功。
