# 服务器快速断联反馈方案（待实施）

## 目标与范围

固件保持不动，先改善服务器对设备突然掉电、网络静默中断的反馈。明确收到关闭事件时立即更新；静默失联目标约 6～9 秒，实际延迟受网络和事件循环调度影响，不承诺严格实时。当前阶段仅规划和备份，不启用新参数。

## 已有基础

- 固件已支持 RFC6455 PING/PONG，无需为服务端主动探测重新烧录。
- 服务器 WSS 当前配置为 ping_interval=10、ping_timeout=20；实现通过 websockets.serve 传入参数。
- MQTT 已执行 1.5 × keepalive 超时、同 client_id 连接替换和 socket 清理；固件 keepalive=60，维持约 90 秒判定，不擅自缩短。
- 状态 hub 已有 mqtt_online。WSS sessions/clients 与历史 hub 记录不同，历史设备记录不能被直接当作在线证据。

## 实施步骤

1. 检查当前 Python websockets 版本及心跳行为，确认 PONG 必须匹配当前 PING；利用库现有机制，不额外叠加一套定时任务。配置改为 ping_interval=3、ping_timeout=6。
2. 在 WSS 连接所有者的退出路径中统一清理 clients、sessions 和语音任务。旧连接退出不得清除新会话状态；单设备会话接管策略暂不扩展为多设备架构。
3. 状态接口明确区分 WSS transport_connected、session_ready/voice_online 与 mqtt_online。WSS 断开立即使语音离线，不等 MQTT。没有活动且完成同步的会话时，不得沿用旧 engine.snapshot 的 online=true。历史设备条目可保留，但应标示历史数据。
4. 对外报告断开原因：正常关闭、PING 超时、异常关闭、会话被替换。PING 超时应读取库提供的实际关闭异常信息，不能把所有 1006 都当作心跳超时；日志记录发现时刻、最后有效 PONG/报文时刻（可获得时）、会话标识。不得记录令牌或完整语音载荷。
5. 重连完成 TLS/认证后仍须收到有效 session_sync 才显示语音就绪；MQTT 恢复单独判定。不发送需要固件新支持的控制指令。

## 验证

- 用隔离端口启动测试服务。客户端完成握手后停止应答 PING但不发 FIN，确认约 6～9 秒内关闭并更新离线状态；覆盖停止响应发生在不同心跳相位的情况。
- 正常 PONG 持续至少 60 秒不误断；连续上行音频不能掩盖下行/PONG链路故障。
- 显式 CLOSE/EOF 立即清理；新旧连接交错关闭不会误伤新会话。
- WSS 离线、MQTT 尚在线时，界面必须显示语音离线，不显示设备完全在线。
- 重连同步 ACK 前不报 voice_online；同步完成后恢复。
- 运行现有状态同步、网络、语音下行和 MQTT 回归测试。
- 真机在 USB、电池两种供电下分别保持联网，并执行断电复测；记录时间。单纯缩短服务器超时不能修复电池压降或设备 TLS 内存错误。

## 发布与回退

实施前保存 Git 基线提交、带注释备份标签、完整 Git bundle，以及包含运行配置/证书/固件的受限访问压缩包。运行日志和虚拟环境不加入源码提交；本次不向远端推送。

后续实现放在独立 codex/ 分支中，测试通过后再重启部署。启动时保留已有运行环境，尤其加载服务器既有 .env 中的 DASHSCOPE_API_KEY，禁止输出密钥。部署后检查 1883/9443/8443、状态接口及语音引擎就绪。

出现误断频繁、状态错乱或语音回归时，回退该次实现提交和参数至基线（10/20），保留已验证的 MQTT 清理修复。不要使用不加区分的 git reset --hard，也不要覆盖并行工作。
