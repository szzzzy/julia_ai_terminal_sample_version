# 源码注释规范

文档版本：V1.1。本文规定 Julia 固件注释应如何记录代码本身无法充分表达的设计信息。返回 [项目入口](../README.md)。

## 1. 注释首先回答什么

代码负责表达“怎么做”；注释只补充删除后会丢失的设计信息。一段有用的注释应优先回答以下问题：

1. 为什么采用当前方案，哪些约束或不变量必须保持？
2. 资源由哪个任务或回调拥有，哪些上下文不得访问？
3. 失败、超时或断线意味着什么，为什么重试、放弃或回退？
4. 参数来自协议、硬件限制、计算还是临时经验；单位和时间基准是什么？

用户或服务器可观察到的结果、跨模块调用顺序和生命周期也是有效内容。变量名、函数名和语句已经表达清楚的行为，不再用中文复述。

## 2. 使用实际含义，不复述变量名

不推荐：

```c
/* s_mic_streaming 为 true，s_dialog_listening 为 false。 */
```

推荐：

```c
/* 默认服务器唤醒模式下，待机时仍上传麦克风供服务器识别唤醒词；
 * 此时设备尚未进入“等待用户说完本轮话语”的阶段。 */
```

不推荐：

```c
/* generation 不一致时丢弃 ring。 */
```

推荐：

```c
/* 连接断开前积压的声音只属于旧连接。重新连接后必须丢弃，
 * 否则服务器会把过期话语误认为新一轮输入。 */
```

## 3. 推荐的注释层次

### 3.1 文件开头

说明模块解决的现实问题、与相邻模块的分工以及最重要的失败边界。不要在第一段堆叠内部函数调用链。

### 3.2 公共接口

说明前置条件、输入输出、所有权、生命周期、是否阻塞、可调用上下文，以及返回成功实际代表什么。参数名和返回类型已经清楚时，不再逐项翻译。

### 3.3 分支与状态变化

解释为什么必须走这个分支。例如“控制连接断开后无法收到结束交流语义，因此当前对话必须退回待机”，比“处理 MQTT disconnect”更有帮助。

### 3.4 并发与资源归属

明确唯一 owner、生产者／消费者、销毁者、锁保护范围和禁止调用的上下文。`Task`、`Queue`、`ISR`、`DMA`、`owner`、`generation`、`ring buffer` 等术语能提高精度时直接保留，不为追求全中文而改写成长句。

## 4. 常用内部词的稳定语义

| 内部词 | 需要补充的设计语义 |
| --- | --- |
| busy | 本轮交流仍未完成，不能进入待机 |
| streaming | 是否正在向服务器发送麦克风声音 |
| listening | 是否正在等待用户完成本轮话语 |
| generation | 当前连接的数据归属编号，用于拒绝旧连接残留数据 |
| owner | 唯一允许操作或销毁该连接、外设或文件的任务 |
| ring buffer | 固定容量及满载策略；生产者何时发布、消费者何时释放 |
| slot | 一项已登记的联网服务或一格待处理消息空间 |
| ready bit | 对应连接、订阅或依赖已经确认可用 |
| teardown | 停止当前工作、释放资源并清除旧状态 |

这些解释用于建立项目内的一致语义，不要求每次出现都重复说明。注释应记录具体约束，例如“旧 generation 不得进入新连接”，而不是把术语逐字换成中文。

## 5. 注释不应做什么

- 不逐行翻译显而易见的赋值、判空或函数调用。
- 不把尚未实现、未测试或仅计划中的能力写成既成事实。
- 不用“显然”“简单”“正常处理”等词代替具体条件和结果。
- 不记录普通修改历史；仍构成当前限制的兼容原因只写现存约束。
- 不写“TODO：优化”一类无执行条件的占位内容；TODO 至少说明触发条件和目标。
- 不为常量虚构“实测”“协议规定”等来源；来源不确定时只写可确认的单位和边界。
- 不给日志标签、局部句柄、简单 getter/setter 或直观分支逐项配字幕。
- 不在公开注释或日志中写入密码、token、私钥、网络凭据或用户语音内容。
- 不复制协议全文；源码说明关键约束，完整报文格式链接到 [通信协议](PROTOCOL.md)。

## 6. 修改与验收

只调整未提交注释时，运行 `python scripts/verify_comments_only.py`；核对一次提交时运行 `python scripts/verify_comments_only.py <base> <target>`。再运行 `python scripts/check_lex_balance.py` 检查块注释和多行宏。涉及行为、协议或配置变化时，还应同步更新 README、协议与验收清单，不能通过修改注释掩盖实现差异。
