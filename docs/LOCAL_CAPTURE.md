## 1. 分工与基线

固件维护唯一底噪状态，负责 20ms 电平、起音、结束、预录及话语编号；云端负责接收校验、人声复核、唤醒词、ASR、噪声判决及原有回答链路。

基线是线上 `/opt/julia-runtime/control-v1-20260910/release/api_server` 的实际源码和已核对的 `voice.real.vad/wake` 配置。源码指纹在 [baseline.json](../cloud/capture-v1/baseline.json)。制作补丁时检查指纹，源码变化后必须重新核对，不能直接覆盖。

默认启用 `CONFIG_JULIA_LOCAL_CAPTURE_ENABLE=y`，依赖服务器唤醒和状态同步配置。未协商 capture-v1 的旧固件仍使用云端既有 PCM1/端点路径；新固件必须收到能力确认后才发送分段音频。内部板级 callback 仍使用 PCM1，WSS 线上新格式为 PCM2。

## 2. 保留的算法

普通对话的收尾抵扣已按后续拖尾优化改为 **1:2**，这是相对迁移基线的明确参数调整。
底噪算法、起音条件、延续电平门槛、700ms 结束门限及15秒上限保持不变；唤醒候选仍为1:4。
该调整减少间歇噪声对收尾的拖延，但会降低对轻声、断续讲话及句中停顿的容忍度。

### 电平及时间

- 固定 16kHz、单声道 PCM16，每帧 320 样本。I2S 短读继续拼帧，避免把短读误算成完整 20ms。
- 保留原来的 I2S 位移、70% 数字增益及 PCM16 饱和裁剪。VAD 使用已经缩放过的 PCM，不再加一次增益。
- `x=PCM16/32768`，`RMS=sqrt(mean(x*x))`，`dBFS=20*log10(RMS)`；零输入返回 −120dBFS。修正了旧板级全零约 −240dBFS 的差异。
- 阈值使用完整精度的本地电平；报文中的百分之一 dB 仅用于传输诊断。C/Python 的浮点累加细微差异通过差分测试约束。
- 统计采用采样时间轴，每帧推进 20ms；任务调度或网络积压不会把相邻帧挤到同一个统计时刻。恢复停止的采音时重新对齐时钟。

### 动态底噪 B

| 项目 | 实现 |
| --- | --- |
| 初值与范围 | 上电 −60dBFS；跟踪及噪声重锚限制为 −80～−35dBFS |
| 更新 | 每 0.5 秒；首次真实有效帧允许一次统计检查 |
| 快窗 | 最近 1.5 秒全部真实帧，不经过门限筛选；至少 20 帧 |
| 慢窗 | 最近 8 秒中，入窗时电平严格低于 `B+12dB` 的候选帧；至少 50 帧 |
| 分位 | 两窗均为第 10 百分位，保留 NumPy 默认线性插值；按时间淘汰，边界相等的帧保留 |
| 上升 | 快窗分位严格高于 `B+1dB`，连续两次确认后每次最多 +1.5dB；持续满足时继续上升 |
| 下降 | 慢窗分位低于 B，每次最多 −0.25dB |
| 快速回落 | 慢窗分位严格低于 `B−6dB` 时直接重锚到慢窗分位，保留下限 |
| 冻结 | 确认起音后，不再向两窗加入本段后续帧，也不更新 B。确认起音的那一帧仍按原代码先更新统计，再判断起音 |
| 中断确认 | 距上次更新超过 1.25 秒，清除上升确认次数；不能跨长冻结期累积“两次确认” |
| 无环境信息 | `≤−100dBFS` 的帧不进入底噪统计 |

正常帧统计之外，为四段迟到判决的回填预留有界空间，保留原 deque 的回填顺序和强制更新行为。采音、预录、判决历史均由麦克风任务拥有，工作内存在 PSRAM；网络任务只投递判决。

### 收音参数

| 参数 | 普通对话 | 唤醒候选 |
| --- | --- | --- |
| 起音 | 严格大于 `B+9dB` | 严格大于 `B+3dB` |
| 起音累计 | 300ms 窗内累计 120ms | 500ms 窗内累计 20ms |
| 延续 | 严格大于冻结后的 `B+3dB` | 同左 |
| 结束 | 静音计数达到 700ms | 达到 500ms |
| 活跃抵扣 | 每 20ms 活跃抵扣 40ms 静音（1:2），最低为零 | 每 20ms 活跃抵扣 80ms 静音（1:4），最低为零 |
| 单段上限 | 750 帧／15 秒，含已上传预录 | 400 帧／8 秒，保留线上监听上限 |
| 预录 | 最多 25 帧／500ms／16,000 字节 PCM | 同左 |

这里的上限是**已发送音频段**的样本数。无起音时持续本地监听，不再把等待起音的静音上传或生成空音频段。

## 3. 典型运行链条

### A. 联网与进入监听

```text
启动并采集 16kHz 音频
→ Wi-Fi / MQTT / WSS 建连
→ session_sync / session_sync_ack 确认设备状态
→ 固件发送 capture_hello（session_id、版本、采样率、stream_generation）
    if 云端支持并确认同一代次：
        开放本地分段入口，保持连接
    else 超过 5 秒仍未确认：
        结束本次 WSS，至少退避 60 秒；不向旧服务器发送 PCM2
```

S3/S5/S6 采用唤醒参数，保留 Wi-Fi、MQTT、WSS 和采音。S1/S4/S2.1 采用普通对话参数。Think、OTA 及不可收音阶段不会起新段；OTA 暂停 MIC I2S。

首轮采用半双工：播放期间暂停本地起音，播放完成后保留 600ms 回声保护，再恢复监听。此边界用于避免没有 AEC 的设备把自己的播报当成用户并立即停播；播放中语音打断尚未纳入本轮新路径，旧固件兼容路径不变。实机需重点检查用户紧跟提示语说话时的首字完整性。

### B. 唤醒候选

```text
每 20ms：计算电平 → 保存 500ms 预录 → 未起音时跟踪底噪
    if 500ms 窗内累计到 20ms 的 B+3dB 活跃音频：
        生成 utterance_id → 冻结 B
        排队 capture_start(mode=wake)
        → 按原顺序补发预录 → 持续发送新音频
    else：
        继续本地监听，静音不上传

段内：按冻结的 B+3dB 更新静音计数
    if 静音计数达到 500ms 或段达到 8 秒：
        最后一帧先排队 → capture_end 后排队
        保持当前 S3/S5/S6；候选段结束不进入 Think

云端：收到开始 → 校验并接收帧 → 可流式送 ASR
       → 收齐明确的 end 才完成本段
    if 人声复核不通过：
        返回 empty 判决，继续监听
    else 识别唤醒词：
        if 命中：
            原有 interaction_sync（严格模式）
            → wake_detected → 固件进入 S4
            → state_ready → 云端播唤醒回应
            → 播完后进入普通收音阶段
        else：
            speech / empty 判决 → 保持监听
```

运动是另一条本地入口：S3/S5/S6 中确认晃动后进入 S4；仍由 FSM 管理显示和语音状态。

S4 与 S2.1 共用听音行为。进入 S4 后，起音事件保持 S4，不再额外切换到 S2.1；段结束直接进入 S2.2。S1 中起音或对话播放被打断仍进入 S2.1，随后同样在段结束时进入 S2.2。

### C. 普通对话

```text
普通参数监听
    if 300ms 内累计到 120ms 的 B+9dB 活跃音频：
        固件生成编号、冻结 B、排队 start 和预录
        → 本地进入“听”并标记 busy
        → 新帧边录边上传

    if 电平 > B+3dB：静音计数 = max(0, 原计数−40ms)
    else：静音计数 += 20ms

    if 静音计数达到 700ms 或上传音频达到 15 秒：
        尾音帧先入同一 FIFO → end 入 FIFO
        → 固件投递本地结束事件，立即进入 Think，无需云端往返
        → WSS 按 FIFO 完整发送尾音后，才在线路上发送 end

云端接收这段话语
→ 对齐原有交互编号/控制结果归属（不下发 MIC_START/MIC_STOP）
→ 人声复核 → ASR → 噪声判决
    if 非人声或无内容：
        返回 empty / noise 判决
        → 原有空轮收尾（短静音播放）→ 固件回 S1
    else if 噪声段：
        返回 noise，丢弃噪声型识别文本 → 空轮收尾
    else：
        返回 speech → 原有意图 / LLM / TTS
        → SPKS / PCM / SPKE → 固件进入“说”
        → 播放任务排空尾音 → S1
        → 连续 10 秒无后续交互进入 S3
```

状态同步优先于音频发送，所以云端可能先看到 Think，再收到积压的 start/end。配套代码允许接收此时已由设备定义的音频段，不会把 Think 当成“无需处理输入”。严格模式仍保留 `interaction_sync` 和执行 ACK，用于结果归属；它们不再承担收音起止控制。

### D. 判决返回后怎样维护底噪

```text
WSS 收到 capture_verdict
→ 检查 session_id、utterance_id、判决枚举
→ 非阻塞投递给麦克风任务
    if 旧连接、历史已淘汰、重复或早于已应用的判决：忽略
    else if 下一段已经起音：先保存判决，等该段结束
    else：
        noise  → 用对应上传段所有帧电平的 P10 重锚，限制到 −80～−35
        empty  → 段至少 400ms 时，按原 feed_segment 回填，并补两次更新
        speech → 不修正底噪
```

云端不直接设置一个新的 B；B 的窗口、冻结、更新及判决应用始终由固件统一维护。原固件已应用的麦克风增益不会因判决重复应用。

### E. 断线、积压和超时

- 开始、预录、实时帧、结束共用上行 FIFO。网络写成功才消费记录；队列满或发送失败终止会话，不能静默丢音后继续识别。
- 每条本地记录带采集时的连接代次。重连／暂停后换代，旧预录、旧未发送段、旧判决不能进入新代次。
- 云端校验长度、PCM2 magic、校验和、段编号、连续帧索引及样本上限；重叠段、序号错误、段尾帧数不符按协议错误关闭连接。
- 没有 end 时不使用合成静音推断一个成功段尾。段内 5 秒无新输入或总接收超过 25 秒视为异常；取消和断线不产生完整 ASR 段。
- 云端已完成的识别不能越过既有会话所有权、控制序号和状态检查。设备原有等待回答／播放超时继续保留。

## 4. 报文

### 握手

```json
{"type":"capture_hello","version":1,"session_id":"...","sample_rate":16000,"frame_ms":20,"stream_generation":10}
{"type":"capture_ready","version":1,"session_id":"...","stream_generation":10}
```

`stream_generation` 改变时，云端取消旧接收器和旧处理任务后重新建立分段入口。相同代次重复 hello 幂等回复。新代次 ACK 之前不发送音频。

### 开始和结束

```json
{"type":"capture_start","utterance_id":42,"mode":"dialog","floor_dbfs":-60.0,"sample_rate":16000,"frame_ms":20,"frames":0,"reason":"silence"}
{"type":"capture_end","utterance_id":42,"mode":"dialog","floor_dbfs":-60.0,"sample_rate":16000,"frame_ms":20,"frames":60,"reason":"silence"}
```

`mode` 为 `wake/dialog`。start 中 reason 无业务含义；end 为 `silence/limit`。模式切换导致未完成段作废时发送 `capture_abort`，不可作为成功 end。

### PCM2 二进制帧

所有整数为 little-endian，总长 656 字节。

| 偏移 | 字段 |
| --- | --- |
| 0～3 | ASCII `PCM2` |
| 4～7 | uint32 `utterance_id` |
| 8～9 | uint16 段内索引，从 0 连续增加，含预录 |
| 10～11 | int16 `dbfs_x100` |
| 12～13 | uint16 PCM 字节数，必须为 640 |
| 14 | 保留，必须为 0 |
| 15 | PCM 字节和的低 8 位 |
| 16～655 | 320 个 PCM16 样本 |

TLS 连接和能力握手绑定 session；start、PCM2、end 的共同话语编号绑定音频段。接收端不接受用旧段编号重开一段。

### 判决

```json
{"type":"capture_verdict","session_id":"...","utterance_id":42,"verdict":"noise"}
```

仅接受 `noise/empty/speech`。严格多设备模式还会附加既有身份与交互字段；底噪反馈以 session 和音频段为归属，不依赖一个可能已经切换的交互状态。

### 固件轮次放行（2026-09-15 修正）

启用本地收音时，普通语音的 `interaction_sync` 成功后直接完成轮次放行，
不再等待 `MIC_START`；重复同步仍返回缓存 ACK。唤醒轮次仍等待 `wake_detected`。
旧 WSS `MIC_START/MIC_STOP` 不产生副作用，带归属的旧控制命令返回
`unsupported_operation`，协商未完成时也不会启动旧收音逻辑。
旧收音处理仅在关闭 `CONFIG_JULIA_LOCAL_CAPTURE_ENABLE` 的兼容构建中编译。
